# careful-factcheck

## 목적

Claude 가 만든 산출물의 **사실·수치·출처를 웹 검색으로 다각도 교차 검증**한다. 결과물의 신빙성이
걱정되는 주장(수수료율, 정산일, 세율, 날짜, 정책 변경, 통계, 고유명사 등)을 그대로 두지 말고,
내장 WebSearch 로 여러 출처를 찾아 읽고 **서로 대조 + 반증 탐색**해 판정한다.

설계 원칙: "검색 한 번으로 나온 답을 그대로 믿지 않는다." perplexity 식 단발 요약보다,
**여러 쿼리 · 여러 출처 · 반증 시도**로 근거의 적절성을 직접 따지는 것이 이 스킬의 핵심이다.

> **이 스킬은 브라우저·CDP·포트 9222·Perplexity·외부 유료 API 를 쓰지 않는다.**
> Claude Code 내장 `WebSearch` / `WebFetch` 만으로 동작하므로 Chrome 확장 연결이나 로그인이
> 사전조건이 아니다. 인터넷만 되면 작동한다.

## 절차

### 1) 주장 추출
검증 대상 텍스트에서 **틀리면 손해가 되는 사실 주장**만 골라낸다 — 수치(수수료율·요율·금액),
날짜·주기(정산일·신고 기한), 정책·규정, 통계, 고유명사·직함. 의견·전망·1인칭 일화는 제외.
각 주장을 **자기완결적 한 문장**으로 정규화한다. 보통 2~5개.

### 2) 쿼리 설계 (주장당 ≥2 쿼리)
한 주장에 대해 **각도가 다른 쿼리 2개 이상**을 만든다. 예) ① 일반 확인 쿼리,
② 반증/예외를 노리는 쿼리("~ 아닌 경우", "~ 변경", "~ 카테고리별"). 최신성이 중요한 주장
(정책·요율)은 연도를 붙이거나 최근 변경 여부를 따로 검색한다.

### 3) 검색 + 출처 확보
`WebSearch` 로 쿼리를 돌리고, 핵심 근거 페이지는 `WebFetch` 로 본문을 열어 **실제 문장을 확인**한다.
출처 우선순위: **① 공식·1차 출처(해당 기업/기관 공식 도메인·약관·고시) > ② 신뢰 매체·정부 > ③ 일반 블로그.**
블로그·요약글만 있으면 단정하지 말고 보수적으로 서술한다.

### 4) 대조 + 반증
- **독립 출처 2개 이상**이 같은 값을 말하는지 확인. 한 곳만 말하면 신뢰도를 낮춘다.
- 출처 간 값이 다르면 그 **불일치 자체를 보고**하고, 더 권위 있는/최신 출처를 채택한다.
- "단일 값"으로 단정된 주장이 실제로는 **조건부·범위·카테고리별**이면(예: "수수료 12%" → 실제 7~13%)
  그 일반화 오류를 명시한다.

### 5) 판정 + 출력
주장별로 판정한다: **✅ 사실 / ⚠️ 부분적·맥락 의존 / ❌ 오류 / ❓ 근거 불충분.**
아래 형식으로 출력한다.

```
## 팩트체크 결과: <전체 한 줄 요약>

| 주장 | 판정 | 실제(근거) |
|---|---|---|
| <정규화된 주장1> | ✅/⚠️/❌/❓ | <확인된 사실 + 핵심 수치> |

### 근거
- <주장별로 어떤 출처가 무엇을 말했는지, 불일치·조건 포함>

**Sources:**
- [출처 제목](URL)
```

## 품질 규칙
- **출처 없는 단정 금지.** 모든 판정에는 클릭 가능한 URL 근거가 붙어야 한다.
- **반증을 빼먹지 않는다.** 주장을 지지하는 근거만 찾고 끝내지 말 것 — 최소 1회는 "틀렸다면 왜 틀렸나"를 검색.
- **최신성 확인.** 요율·정책은 옛 글이 상위에 뜰 수 있으니 변경 이력을 따로 확인.
- **불확실하면 ❓로 남긴다.** 모르면 모른다고 한다. 추측으로 메우지 않는다.
- Read-only. 어떤 사이트에도 글 작성·전송·로그인 변경을 하지 않는다.

## 언제 deep-research 로 올릴까
주장이 많거나(>5), 1차 출처가 흩어져 있거나, 틀리면 손해가 큰 핵심 수치라면
**`deep-research` 스킬**(멀티소스 fan-out + 적대적 검증 + 인용 리포트)로 격상한다.
이 스킬은 그보다 가볍고 빠른 "발행 전 1차 검증" 용도다.
