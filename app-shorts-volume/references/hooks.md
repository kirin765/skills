# 완주율 훅 공식 (Stage 1)

왜 이게 중요한가: 콜드스타트 증폭은 **초기 수백 노출의 완주율**이 정한다(arXiv 2507.09423). 조회수는 결과이지 통제
변수가 아니다. 우리가 만질 수 있는 건 **첫 3초에 이탈을 막고, 끝까지 보게 만드는 구조**뿐이다. 그래서 훅 설계 = 이 스킬의
실질 승부처다.

## 첫 3초 원칙

1. **첫 프레임에 이미 움직임/결과가 있어야 한다.** 로고·인트로·"안녕하세요" 금지 — 그 순간 스크롤당한다.
2. **긴장을 먼저 걸고 해소를 미룬다.** 결과·변화·질문을 앞에 두고, "어떻게?"를 뒤로 미뤄 완주를 유도.
3. **자막(on-screen text)으로 훅을 이중화.** 소리 없이 봐도 훅이 읽혀야 한다. 한국 시청은 무음 비율이 높다.
4. **앱을 광고하지 말고, 앱이 푸는 문제/결과를 보여준다.** "이 앱 써보세요"가 아니라 "이거 3초 만에 됨" → 앱은 수단으로 등장.

## 훅 패턴 (변형을 이 계열로 뽑는다)

같은 앱, 훅만 다른 N개를 만들 때 서로 다른 계열에서 뽑아야 어느 계열이 먹히는지 측정된다.

- **결과 먼저(Result-first)**: 완성/전후 결과를 0초에 보여주고 → "이렇게 만든 법" 역순 전개.
- **문제 공감(Pain)**: 타깃이 매일 겪는 짜증을 3초 안에 정확히 찌른다 → 앱이 해소.
- **의외성(Pattern-break)**: 예상과 다른 전개/숫자/사실로 스크롤을 멈춘다.
- **호기심 갭(Curiosity gap)**: "대부분 이거 모름" / "이 기능 숨겨져 있음" → 확인하려고 끝까지 봄.
- **실시간 시연(Live demo)**: 편집 없이 한 번에 되는 걸 보여줘 신뢰. 게임 앱이면 플레이 하이라이트.
- **리스트/카운트다운**: "무료 앱 3개" 식 — 완주 동기(끝까지 봐야 다 앎)를 구조가 만든다.

## 본문·CTA

- **본문은 훅의 약속을 빠르게 지킨다.** 늘어지면 중도 이탈 → 완주율 하락 → 증폭 실패.
- **루프(loop)**: 끝이 처음과 이어지게 만들면 재시청률↑ (YouTube·TikTok 완주 지표에 유리).
- **CTA는 부드럽게, 늦게.** 초반 "앱 다운로드하세요"는 이탈 유발. 앱 이름/설치는 끝이나 캡션·고정댓글로.

## 안티패턴 (완주율을 죽인다)

- 인트로·로고·브랜딩 3초 낭비
- 무음에서 안 읽히는 훅(자막 없음)
- 앱 UI 설명충 — 기능 나열은 완주율 킬러. 문제→결과만.
- 타 플랫폼 워터마크(IG/YT 추천 억제)
- 세로 규격·안전영역 무시(자막이 UI에 가림)

## 변형 설계 산출물 (Stage 1 결과)

각 변형마다:
```
변형 #: <훅 계열 이름>
0-3s 훅: <첫 프레임에서 보이는 것 + 자막 문구>
본문 비트: <3~5개 컷의 흐름>
CTA: <언제/어떻게 앱을 노출>
루프 여부: <끝→처음 연결 가능한가>
```
