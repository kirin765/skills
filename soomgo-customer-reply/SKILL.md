# 숨고 고객 응대 (견적 초안 작성)

숨고 받은요청을 확인하고, 견적서 초안을 작성해 사용자 승인 후 발송하는 스킬.

## 중요: 완전 자동발송 아님

**견적서 발송은 매번 사용자 확인 후에만 진행한다.** 이유 두 가지:
1. 숨고는 견적서 1건 발송마다 **유료 캐시가 소모**된다 — 블라인드 자동발송은 실탄을 허비할 위험.
2. 외부 플랫폼에 메시지/양식을 제출하는 행위는 매번 사용자 승인이 필요한 행동이다.

이 스킬의 산출물은 **"바로 제출 가능한 초안"**이지, 무인 자동응답기가 아니다. 초안을 사용자에게 제시하고, 명시적 승인("보내줘", "제출해줘" 등)을 받은 뒤에만 실제 발송 버튼을 클릭한다.

## 사용자 정보

- 활동명: 봇메이커 (크몽과 동일 브랜드)
- 실제 운영 중 사이트 10개 이상 — reviewboost.co.kr, sajangbu.com 등
- 경력: 컴퓨터공학 전공, 정보처리기사, IT보안회사 백엔드 1년 5개월 + 프론트엔드 인턴 6개월
- 활동 지역: 경기 광명시
- 등록된 서비스 카테고리 (2026-07-08 기준, `soomgo.com/profile/services`):
  1. **챗봇 개발** — 세부항목: 카카오톡, 텔레그램
  2. **웹 개발** — 세부항목: 신규 제작, 기존 웹 리뉴얼
  3. **웹/앱 유지보수** — 세부항목: PC 웹, 모바일 웹
  4. **데이터 크롤링** — 세부항목: 웹 크롤링

## 워크플로우

### 1. 받은요청 확인

Chrome CDP(사용자의 인증된 세션)로 접속. `cdp-anywhere` 패턴과 동일하게 이미 로그인된 브라우저를 사용 — 별도 로그인 불필요.

- URL: `https://soomgo.com/requests/received`
- 각 요청의 카테고리, 예산, 지역, 상세 내용, 게시 시각을 확인
- 이미 견적을 보낸 요청(발송 완료 표시)은 건너뜀

### 2. 응답 필터 (캐시 낭비 방지)

**견적을 보낸다:**
- 예산이 명시돼 있고 services.md 기준표 범위와 크게 어긋나지 않음
- 사업자/법인 정황이 있거나 요구사항이 구체적임
- 등록된 4개 서비스 카테고리 중 하나에 명확히 해당

**거른다 (견적 미발송):**
- 유흥업 관련 의뢰
- 예산 없이 "얼마예요?"류 초단문 요청
- 크롤링 금지 대상(로그인 우회, CAPTCHA 우회, 개인정보 수집, 약관상 크롤링 금지 사이트)
- 학생 과제·비영리 봉사 정황이 뚜렷한 경우
- 요구사항이 너무 모호해 확정 견적이 불가능한 경우 → 이 경우도 발송하지 말고 사용자에게 보고만

### 3. 견적서 초안 작성

`references/services.md`의 가격 기준표를 그대로 사용한다(표 밖의 금액을 만들지 않는다). 견적서 구성:

- **금액**: 기준표 패키지 중 가장 가까운 것. 요청 범위가 애매하면 최소 패키지 + "정확한 범위 확인 후 조정 가능" 명시
- **작업 기간**: 서비스별 기준표의 작업일
- **견적 설명 (2~5문장)**:
  - 인사말 + 핵심 차별점 1줄("직접 만들어 운영 중인 서비스 10개 이상")
  - 요청 내용에 대한 구체적 이해를 보여주는 1~2문장 (복붙 티 나지 않게)
  - 확정 견적을 위해 필요한 자료 요청 1개 (전환규칙 반영: 진입장벽 낮추는 대안 제시)
  - 마지막 줄: 다음 행동 ("자료 주시면 당일 확정 견적 드립니다" 등)

**가격 쇼크 완화** (kmong-customer-reply와 동일 규칙): 요청서에 적힌 예산 대비 10배 이상 견적이 나오면, 전체 금액만 던지지 말고 최소 패키지로 범위를 축소한 대안을 함께 제시한다.

**안티셀링 금지**: "시중에 더 나은 서비스가 있을 것 같다", "제가 실무 경험이 부족하다" 류의 자기 축소·경쟁사 추천 금지.

### 4. 사용자 제시 → 승인 대기

작성한 초안을 사용자에게 보여주고 승인을 기다린다. 형식:

```
[요청 N] 카테고리 · 예산 · 지역
요청 내용 요약: ...

견적 초안:
금액: ___원
기간: ___일
설명: "..."

→ 보내도 될까요?
```

여러 건이 쌓였으면 한 번에 모아서 제시하되, 발송은 건별로 승인받는다(일괄 승인도 사용자가 명시하면 가능).

### 5. 승인 후 발송

사용자 승인이 확인된 건만 실제로 견적서 제출 폼을 채우고 제출 버튼을 클릭한다.

## 숨고 정책 (절대 위반 금지)

- 이메일, 전화번호, 회사명, 회사 홈페이지 등 외부 연락 수단을 견적서 본문에 게시하지 않는다 — 게시 시 자동 삭제되고 서비스 이용이 제한될 수 있음
- 과장 표현("국내 최고", "100% 보장" 등) 금지
- 플랫폼 외부 직거래 유도 금지

## 답변 톤 가이드

- 존댓말, 2~5문장, 명확하고 간결하게
- 금액은 항상 "원" 단위 숫자로 명시
- 모호한 요청에는 추측 대신 확인 질문
- 크몽과 동일 브랜드("봇메이커")이므로 톤·포지셔닝 일관성 유지
- **어미는 합쇼체로 통일**: "~했습니다/~입니다/~합니다/~됩니다". "~해요/~네요" 같은 요체, "~다/~본다" 같은 평서체(문어체) 둘 다 쓰지 않는다. 첫 인사말 "안녕하세요"만 관용구로 예외 허용.
- 어휘는 컨설팅펌 격식 단어(재량권, 신뢰도 등) 대신 평이한 표현 사용 — 다만 일부러 어색하게 쓰지는 않고 자연스러운 실무자 말투 수준 유지.
- 문장은 짧게 끊고 "다만/일단은/그 다음에" 같은 접속어로 연결. 항목이 여럿이면 번호(1~2, 3, 4)로 구분하되 불릿(•) 대신 문단 서술.
- 마무리는 항상 다음 행동 요청으로 끝맺음(예: "정해주시면 그에 맞춰 견적을 드리겠습니다").
