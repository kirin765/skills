# 크몽 고객 문의 응대

크몽 메시지함을 읽고, 서비스 지식에 맞는 답장 초안을 만들어 **사용자 승인을 받은 뒤** 발송하는 스킬이다.

## 핵심 원칙 (가장 중요)

1. **발송 전 반드시 사용자 승인.** 초안을 보여주고 명시적으로 승인받기 전에는 절대 전송 버튼을 누르지 않는다. 승인은 메시지 1건마다 받는다. 자동화된(무인) 실행에서는 발송 자체를 하지 않고 초안만 보고한다.
2. **견적은 `references/services.md`의 기준표에서만 산출한다.** 즉석 할인이나 기준 밖 금액을 만들지 않는다. 견적이 흔들리면 고객 신뢰가 깨진다 — 과거 이 계정은 즉석 견적으로 거래를 놓친 적이 있다.
3. 크몽 정책 준수: 직접 결제(계좌이체) 유도 금지, 외부 연락처(전화·카카오톡) 교환 금지.

## 워크플로우

### 1. 메시지함 확인
- `tabs_context_mcp`(createIfEmpty)로 탭 확보 후 `https://kmong.com/inboxes` 로 이동한다 (로그인되어 있다고 가정, 안 되어 있으면 사용자에게 알린다).
- "안 읽음" 필터를 눌러 새 문의를 확인한다. 사용자가 특정 고객을 지목했으면 해당 대화를 찾는다.
- 새 문의가 없으면 그렇게 보고하고 종료한다.

### 2. 대화 읽기
- 각 대화를 열고 `get_page_text`로 전체 맥락을 읽는다. 우측 패널의 고객 정보(회원 구분, 거래수)와 "문의 서비스"(어떤 서비스에 대한 문의인지)도 확인한다.
- 고객의 최신 메시지뿐 아니라 이전 대화에서 이미 안내한 금액·조건이 있는지 본다. **이미 안내한 확정 견적과 모순되는 답을 만들지 않는다.**

### 3. 초안 작성
- `references/services.md`를 읽고 그 지식과 원칙에 따라 초안을 만든다.
- 톤: 존댓말, 2~5문장, 명확하고 과장 없이. 끝에 다음 행동(자료 요청, 결제 안내 등) 한 줄.
- **어미는 합쇼체로 통일**: "~했습니다/~입니다/~합니다/~됩니다". "~해요/~네요" 같은 요체, "~다/~본다" 같은 평서체(문어체) 둘 다 쓰지 않는다. 첫 인사말 "안녕하세요"만 관용구로 예외 허용.
- 어휘는 컨설팅펌 격식 단어(재량권, 신뢰도 등) 대신 평이한 표현 사용 — 다만 일부러 어색하게 쓰지는 않고 자연스러운 실무자 말투 수준 유지.
- 문장은 짧게 끊고 "다만/일단은/그 다음에" 같은 접속어로 연결. 항목이 여럿이면 번호(1~2, 3, 4)로 구분하되 불릿(•) 대신 문단 서술.
- 정보가 부족해 견적을 확정할 수 없으면, 범위(예: "20~50만원")를 안내하고 확정에 필요한 자료(참고 사이트, 페이지 구성, 소스코드 등)를 요청하는 초안을 만든다.
- 지식에 없는 기능·기술 가능 여부를 묻는 문의면 함부로 약속하지 말고 "확인 후 답변드리겠습니다" 초안 + 사용자에게 실제 가능한지 질문.

### 4. 승인
- 대화별로: 문의 요약(2줄) + 초안 전문을 보여주고 AskUserQuestion으로 묻는다: **승인(발송) / 수정 요청 / 건너뛰기**.
- 수정 요청이면 피드백을 반영해 다시 승인을 받는다.

### 5. 발송 (승인된 것만)
- 해당 대화의 입력창을 클릭하고 승인된 초안 텍스트를 입력한 뒤 전송 버튼을 누른다.
- 발송 후 스크린샷으로 정상 전송을 확인한다. 줄바꿈이 Enter로 전송을 유발할 수 있으니, 여러 문단이면 입력 후 화면을 확인하고 전송한다.

### 6. 마무리 보고
- 처리 결과를 표로 요약: 고객명 / 문의 요지 / 처리(발송·보류·건너뜀).
- 견적을 새로 안내한 경우 그 금액을 명시해 사용자가 기록할 수 있게 한다.

## 거절·주의 문의

`references/services.md`의 "거절 기준"에 해당하면(유흥업, 법적 문제 소지 크롤링 등) 정중한 거절 초안을 만들고, 그 사유를 사용자에게 알린다. 판단이 애매하면 발송하지 말고 사용자에게 묻는다.

## 온디맨드 CDP 트리아지 모드 (권장 · 폰 원격 대응 포함)

위 워크플로우는 Claude-in-Chrome 확장으로 대화를 하나씩 클릭해 읽는다. 그 대신 **CDP(포트 9222) + Playwright 스크립트**로 인박스를 한 번에 감지·초안·발송하는 모드다. 스레드가 많거나, 폰(Claude 모바일 앱)에서 원격으로 돌릴 때 쓴다. **승인 게이트는 이 모드에서도 불변** — 발송은 승인된 것만.

### 전제조건
- 맥에서 Chrome이 `--remote-debugging-port=9222 --user-data-dir=~/chrome-cdp-profile` 로 떠 있고 **그 프로필이 크몽 로그인 상태**. (상주 launchd: `~/.remote-trigger` 참조. 폰-온리면 필수.)
- 세션 cwd는 `~/projects/misc/brain` (Playwright가 여기서 resolve됨).
- 9222가 없으면 `triage.mjs`/`send.mjs` 가 먼저 CDP 전용 Chrome(chrome-cdp-profile) 자동 기동을 시도한다(최대 15초, 맥 로컬 세션 전제 — 폰 원격 트리거도 같은 맥에서 실행되므로 동일하게 동작). 그래도 실패하면 `{"ok":false,"error":"no-cdp"}` 를 반환 → 사용자에게 알리고 중단(폰이면 Telegram).

### 1. 트리아지 (읽기 전용)
```
node "<이 스킬>/scripts/triage.mjs"
```
- 내부 API GET(`/api/v5/inbox-groups`, `/{id}/messages`)만 사용 → **클릭·읽음처리 없음.** 스레드별 `{name, url, gig{title,price,category}, last_message_mine, unread, messages[]}` JSON을 출력.
- `last_message_mine`은 **원신호일 뿐 분류가 아니다.** 분류는 마지막 메시지 텍스트를 읽고 Claude가 판단한다:
  - **needs_reply** = 고객의 마지막 메시지가 **답을 기다리는 질문·요청**. (`last_message_mine=false` 이면서 닫는 인사가 아닐 때)
  - **done** = 종결. 특히 `last_message_mine=false`여도 마지막이 **"감사합니다/넵/좋은하루" 같은 닫는 인사**면 done (⚠️ 실측: 이걸 needs_reply로 오판하기 쉬움 — 반드시 텍스트로 확인).
  - **needs_followup** = 내가 마지막(`last_message_mine=true`)인데 **견적·자료요청을 보낸 뒤 3일 이상 무응답 + 팔로업 이력 없음**(services.md 전환규칙 1). 3일 미만이면 대기(=아무것도 안 함).
  - 유흥/불법 크롤링 문의는 services.md 거절 기준 → 거절 초안(또는 이미 거절했으면 done).

### 2. 초안
- `references/services.md`의 서비스·견적표 + **전환 규칙 5종**(안티셀링 금지·즉흥견적 금지·가격쇼크 완화·추가일감 접수·불가능 선언 전 우회로)에 맞춰 needs_reply/needs_followup만 초안 작성.

### 3. 승인 (폰에서도 동일)
- 스레드별 AskUserQuestion: **승인(발송)/수정/건너뛰기.** 폰(모바일 앱)에서 그대로 탭·회신으로 답할 수 있다.

### 4. 발송 (승인분만)
- 승인된 것만 jobs 파일로 모아 발송:
```
# jobs.json = [{"url":"...inbox_group_id=..&partner_id=..","text":"..."}]
node "<이 스킬>/scripts/send.mjs" <jobs.json>          # 실발송
node "<이 스킬>/scripts/send.mjs" <jobs.json> --dry-run # 입력만·전송 안 함(검증)
```
- `pressSequentially`로 실제 키입력(한글 mojibake 방지) → 전송 클릭 → 스크린샷 검증. `--dry-run`은 창에 채우고 스크린샷만.

### 폰 트리거 (참고)
- iOS Shortcut → `cc.sajangbu.com/start`(Bearer) `{dir:"~/projects/misc/brain"}` → 맥에 brain `claude remote-control` 세션 기동.
- **remote-control은 첫 프롬프트를 폰에서 받는다**(서버가 프롬프트를 주입할 수 없음 — tmux 페인은 브리지 상태화면). 폰에서 앱을 열고 "크몽 응대"를 입력하면 이 모드가 발동. 어차피 승인하러 앱에 들어오므로 문구 한 줄이 시작점.
