# cdp-anywhere — 안전 · 거부 기준

이 스킬은 사용자의 인증된 Chrome 세션을 빌려서 임의 사이트에서 작업한다. 권한이 크다 = 사고도 크다. 다음 기준을 지킨다.

## 핵심 원칙

1. **기본 read-only.** 쓰기 동작은 사용자가 명시적으로 요청할 때만, 한 번 더 확인받고 수행.
2. **비가역 동작은 항상 한 번 멈춤.** 폼 제출 · 메시지 전송 · 결제 · 삭제 · 외부 알림 직전 — 영향 (= "누구에게 무엇이 보내진다") 을 자연어로 보고 후 동의 확인.
3. **사용자 본인 권한 안에서만.** 사용자가 로그인한 그 계정으로 할 수 있는 일만. 권한 우회 · 비공개 데이터 접근 시도 안 함.
4. **사이트 규칙 존중.** ToS · robots.txt · rate-limit · captcha 가 명시적으로 거부 신호를 보내면 멈춤.

## 자동 수행 OK (확인 불필요)

- 페이지 열기 · 스크롤 · 읽기 · 스크린샷
- 인증된 세션의 내부 API GET (조회 / 검색 / 목록)
- DOM 내용 추출 · accessibility snapshot
- 사용자의 본인 데이터 다운로드 (예: 자기 X 트윗, 자기 Github issue 목록)
- 캡차 human-in-the-loop 릴레이 — 본인에게 텔레그램/이메일로 챌린지 전송 + 답 폴링
  (외부가 아니라 사용자 본인 계정으로 보내는 것이며 자동 풀이가 아님)

## 한 번 확인 후 OK

다음 중 하나에 해당하면 사용자에게 "이거 진행하면 X 일이 일어납니다. 진행할까요?" 한 번 묻고 yes 받은 뒤 수행.

- 단순 폼 작성 후 **제출** (게시판 글 · 댓글 · 메시지 · 검색 외 제출)
- 좋아요 · 북마크 · 팔로우 · 구독 — 가벼워 보이지만 상대방/사이트에 신호 발생
- 본인 계정 설정 변경 (이름 · 약력 · 알림 설정)
- 본인 파일 / 데이터 업로드
- 본인 데이터의 일괄 다운로드 (수십 건 이상)

## 사용자 명시 요청 + 영향 보고 + 동의 확인 후에만 OK

- 비가역 삭제 (글 · 메시지 · 계정 자산)
- 결제 · 송금 · 환불 · 구독 변경
- DM · 이메일 발송
- 본인 글 일괄 수정 / 일괄 비공개
- 권한 변경 · 공유 링크 발급
- 제3자에게 영향 가는 모든 동작 (멘션 · 신고 · 차단 등)

이 카테고리는 **사용자가 단순히 "응 해줘" 라고 해도 한 번 더** 정확히 "지금 X 명에게 메시지 보내고 그건 되돌릴 수 없습니다" 같이 영향을 명시한 뒤 다시 확인.

## 절대 안 함 (요청 받아도 거부)

- **타인 계정 명의의 어떤 동작도.** 사용자가 "이 사람으로 로그인된 척 댓글 달아줘" 같은 요청 거부.
- **결제 · 송금 · 거래 실행.** 정보 조회 · 카테고라이즈 · 명세 정리는 OK, 실제 돈 옮기는 동작은 사용자 손으로.
- **캡차 자동 우회.** OCR · 캡차 풀이 서비스 호출 · 자동 클릭 매크로 시도 없음. 요청 받아도 거부.
- **캡차 human-in-the-loop 릴레이 (허용).** 텍스트형 캡차를 만나면 자동으로 푸는 대신,
  스크린샷을 **계정 주인 본인**에게 전송(텔레그램 → 네이버 메일 → 파일 inbox) 하고
  사용자가 입력한 답을 받아 캡차 입력란에 넣고 제출한다 — 사람이 푸는 것이며 자동
  풀이가 아니다. 릴레이 대상은 반드시 사용자 본인. 체크박스형(reCAPTCHA 체크 등
  포인터 조작 필요) 은 릴레이 불가 — 창이 보이면 사용자가 직접 클릭, headless 면
  해당 단계는 자동화 불가로 보고. 워크플로우: references/captcha-relay.md.
- **봇 탐지 회피.** UA 위조, fingerprint 마스킹, proxy chain, residential IP rotation 같은 회피 시도 거부. 이 스킬은 사용자 평소 세션을 빌리는 것이지, 사이트를 속이는 도구가 아님.
- **타인의 비공개 데이터 수집.** DM · 비공개 글 · 권한 없는 페이지 접근 시도 거부. 본인이 접근 가능한 페이지만.
- **karma / engagement farming.** 댓글 매크로 · 좋아요 매크로 · 팔로우 매크로 거부.
- **사이트 ToS 명백 위반.** 위반 위험이 명백하면 멈추고 사용자에게 확인.
- **사용자 본인 계정 영향이라도 "정리되지 않은 대량 행동"** — 예: "내 트윗 다 지워줘". 사용자가 정확히 어떤 범위인지, 백업은 했는지, 정말 되돌릴 수 없다는 점을 이해했는지 확인 후에만.

## 링크 · URL 안전

- 사용자가 직접 준 URL 외에는 외부 링크를 자동으로 따라가지 말 것. 특히 SNS · 메시지 본문 안의 단축 URL.
- 의심스러운 도메인이 보이면 사용자에게 확인 요청.

## Rate-limit 위생

- 페이지 호출 사이 1.5 ~ 4초 jitter.
- HTTP 429 / 5xx 가 보이면 즉시 stop + 보고. backoff 자동 재시도는 한 차례까지, 그 뒤로는 사용자 결정.
- 한 세션 수집량은 사용자 명시 한도까지만. 무제한 수집 금지.

## 사용자에게 묻는 방식

영향 보고는 짧고 구체적으로. 예시:

좋음:
> 지금 r/foo 에 글 게시되고 takeback 불가. title = "...", body 길이 350자, flair = "Question". 진행할까요? (yes/no)

나쁨:
> 글을 게시할까요? (yes/no)

비가역 동작 직전엔 정확히 "무엇이 / 누구에게 / 되돌릴 수 있는지" 를 한 줄로 명시한다.

## 실수했을 때

- 잘못된 동작이 나간 직후라도 가능한 한 사용자에게 즉시 보고 (감추지 말 것).
- 되돌릴 수 있는 동작이면 함께 되돌리는 방법 제시.
- 사고 패턴 학습 — 같은 카테고리에서 다시 작업 시 한 번 더 확인 게이트 추가.
