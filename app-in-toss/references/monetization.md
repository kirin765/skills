# 수익화 — 인앱 결제(IAP) + 인앱 광고 3종 + 광고 그룹 ID 조직

앱인토스 공식 문서 실측 요약. 원문: [인앱 광고](https://developers-apps-in-toss.toss.im/guide/monetization/in-app-ad.md) · [인앱 결제](https://developers-apps-in-toss.toss.im/guide/monetization/in-app-payment.md) · [전면/보상 광고 API](https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/interstitial-rewarded-ad.md) · [배너(WebView)](https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/web-banner.md).

## 공통 선행: 사업자 정보 → 약관 동의 → 정산 정보

광고·결제 수익을 정산받으려면 워크스페이스 '정보' 탭에서 정산 정보 등록 → 검토(영업일 평균 2~3일). **예금주명은 통장 사본과 한 글자도 다르면 안 됨**(정산 지연). IAP 수익은 익월 말 입금, 광고 성과는 매일 10시 업데이트.

## 인앱 결제(IAP)

### 상품 규칙 (콘솔)
- **유형 3종**: 소모품(재구매 필요 — 게임 아이템·재화·1회 이용권) / 비소모품(광고 제거·소장 콘텐츠) / 자동 갱신 구독(매주 7일·매월 30일·매년 365일 주기).
- **상품 수 제한**: 게임 80개 / 비게임 30개.
- **상품명**: 받는 기능·조건을 그대로. 과장·오해 금지(기간 한정인데 "무제한" 금지).
- **상품 이미지**: 1024×1024. "30일 이용권","100코인" 같은 식별 텍스트 허용. 이벤트 문구는 기간 표기 필수.
- **공급가**: VAT 제외. **최소 400원 ~ 최대 1,400,000원, 10원 단위**. 판매가는 공급가+VAT로 자동 계산(판매가 먼저 입력 불가).
- **소모품 할인**: 노출 중 상품에만 설정 가능, **등록 후 수정 불가**. 대상: 전체 / 결제 이력 없음 / 결제 이력 있음. 할인 상품 기구매자는 추가 할인 불가. 환불도 구매 이력 포함.
- **구독 전용**: 무료 체험(3일·1주·2주·1개월) · 신규 구독 할인 · 재구독 할인.
- **결제 알림 URL**: 구독 갱신·해지 등 상태 변경 시 HTTP 요청(선택적 Basic Auth 헤더).
- **금지**: 현금성·환가성 상품, 토스 포인트와 결합해 제공하는 상품.

### 수수료 · 환불
- 수수료 = **앱마켓 15%(매출에 따라 변동 가능) + 토스 5%**.
- 환불: Android는 토스 앱에서 사용자 요청 → 콘솔 '환불 내역'에서 승인/반려(최종 판단은 Google Play). **iOS는 Apple이 전권**(파트너는 상태 조회만).

### 지표
- 매출(총 결제액·결제자당 평균·재결제) · 사용자(결제율·최종 전환율). 데이터는 D+1 오전 8시부터 순차 갱신.

## 인앱 광고 3종

수익 = 노출 수 × eCPM ÷ 1,000. 세 유형을 조합하면 단일 사용보다 수익 상승.

| 유형 | 특성 | 추천 위치 | 노출 | eCPM |
|---|---|---|---|---|
| 전면형(Interstitial) | 강제 노출(무시 불가) | 화면 전환 직전·직후, 레벨 완료·결과→다음 단계 같은 '흐름이 끊기는 순간' | 중간 | 중간 |
| 리워드(Rewarded) | 자발적 시청·집중 최고 | 보상 순간: 이어하기, 추가 혜택, 포인트·아이템 지급 | 낮음 | 최고 |
| 배너(Banner) | 상시 고정, 자동 트래픽 | 메인·리스트·사용 시간 긴 화면의 상단/하단 | 최다 | 최저 |

## 콘솔 광고 그룹 생성 → ID 수집 (핵심 워크플로)

1. **광고 그룹 이름** — 유형+위치를 함께 적어 운영 중 구분되게: `메인_전면광고`, `게임종료_리워드광고` 식.
2. **광고 유형** — 배너/전면형/리워드.
3. **리워드(리워드 유형만)** — 사용자에게 실제 지급하는 보상명+수량(서비스 내 용어와 동일): "기회 / 1".
4. **미디에이션** — 앱 정보 카테고리에 맞는 광고 네트워크가 자동 설정. 바꾸면 **앱 정보에 반영되지 않고 해당 광고 그룹 생성에만 적용**.
5. 생성 후 **상세 화면에서 광고 그룹 ID 확인**. 구글 등록까지 **최대 2시간** 소요 가능. 이 ID로 개발.

### 광고 그룹 ID 조직 방법 ("take ads group id and think where organize ads")

- **상태 식별**: 예시 ID 패턴 — 개발/테스트 `ait.dev.<32hex>` · 라이브 `ait.v2.live.<32hex>`(운영 코드 기준) · 공식 테스트 ID `ait-ad-test-interstitial-id` / `ait-ad-test-rewarded-id` / `ait-ad-test-banner-id`. ID만 보고 dev/live를 구분하기 어려우니 그룹 이름에 단계를 넣거나(dev_게임종료_전면) 코드에서 env로 분리한다.
- **코드 배선은 3개 상수 또는 env 3개**: `REWARD_AD_GROUP_ID` · `INTERSTITIAL_AD_GROUP_ID` · `BANNER_AD_GROUP_ID`. 빌드 시 `VITE_*_AD_GROUP_ID` env로 주입하면 dev→live 전환을 재빌드 없이 하거나 브랜치로 분리할 수 있다. 값은 스킬·문서에 하드코딩하지 말 것.
- **광고 타입은 그룹 ID로 자동 결정**(전면/리워드 동일 `loadFullScreenAd` API). 그룹을 잘못 만들면 원하는 타입이 안 나오므로, 유형별 그룹 1개씩 만들고 ID를 서로 바꿔 쓰지 않는다.
- **배치는 게임 플로우 기준으로 정한다** — 전면: 게임 오버·스테이지 클리어 직후(사용자가 멈추는 순간), 세션당 횟수 제한 권장(강제 노출이라 피로도 관리). 리워드: 부활/추가 생명/하트 충전/보너스(시청 완료 시에만 지급). 배너: 플레이 중이 아닌 화면(홈·설정) 하단 고정 — 게임 조작 영역·CTA 인접 금지.
- **채널×오퍼 분리 측정**(원장 규칙): 광고 그룹 3종은 각각 노출·eCPM·수익이 별도 집계됨(콘솔 분석). 유입(혜택탭·푸시) 실측과 결제 실측을 같은 광고 그룹 지표와 섞지 않는다. IAP 결제는 게이트 실측, IAA는 익월 정산이라 단기 게이트 실측 불가 — 별도 트랙으로 본다.

### 광고 정책 (위반 시 제한·정산 보류·환수)

- **UI/UX**: 광고는 "Ad" 표기 유지 · web-base 표준 컴포넌트만 · 같은 화면에 같은 포맷 2개 이상 금지 · 버튼·게임 플레이 영역에 인접 배치 금지(의도치 않은 클릭) · 광고를 "추천 서비스"로 위장 금지 · 막다른(dead-end) 구조 금지 · 광고 색·글꼴·CTA 임의 수정 금지.
- **호출 동작**: SDK Click/Impression 이벤트 변조 금지 · SDK 밖 자체 호출 금지 · Back 버튼 차단 금지.
- **비정상 트래픽**: 광고 영역 주기적 refresh 금지 · 인위적 성과 발생 금지(트래픽 품질 위반 시 제재).
- **보상·참여형 클릭 유도 금지**: "광고 클릭 즉시 리워드" 금지. 리워드는 **시청 완료** 기준이어야 함.
- **은닉/겹침 금지**: 투명 광고·다른 카드 뒤에 광고 DOM 금지.
- **테스트**: 반드시 테스트용 ID. 운영 ID로 테스트하면 제재. 광고 재생 중 앱 사운드 일시정지·종료 후 재생.
- 제재 절차: 단계적, 중대 위반은 30일/영구 제한. 통지 후 30일 내 채널톡 이의제기(위반 사실·판정 오류 중심 심사 — '수정했음'만으로 해제 안 됨).

### 광고 분석 (SDK 2.7.0+)
- 노출 현황: 요청→수신→노출 시도→노출 성공 퍼널로 디버깅(요청 대비 수신 낮음=No Fill, 수신 대비 시도 낮음=load/show 타이밍, 시도 대비 성공 낮음=SDK/순서).
- 유형별 빈도·eCPM: 빈도↑ eCPM↓ = 광고 피로도. 리워드 eCPM이 높으면 리워드 비중 확대 검토. OS별 비교 가능.
